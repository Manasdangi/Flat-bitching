# Supabase schema v2 (applied 2026-11-03 via migrations in the Supabase project)

- `reviews`: + `society`, `r_clean`, `r_safety`, `r_water`, `r_power`, `r_drain` (1–5, optional), `hidden`.
  Select policy: `not hidden`. Before-insert trigger (`private.reviews_set_created_at`) stamps time, forces visible,
  and rate-limits: 1 review per sector per 24h and 5 per 24h per device (`x-device-id` header) or IP hash.
- `review_meta` (private: RLS on, no policies): device id + SHA-256 IP hash per review.
- `review_reports`: insert-only. 3 distinct IPs reporting the same review sets `reviews.hidden = true`.
- `corrections`: insert-only resident suggestions (`topic`, `message`, `status`), max 10/day per IP.
  Review them in Table Editor → corrections.
- `sector_shapes`: OSM sector outlines (GeoJSON, simplified) + corrected centre point. Public read.
- `drive_times`: OSRM road km + off-peak minutes, sector → tech hub. Public read.
- Trigger functions live in schema `private` (not exposed through the API).

Build-time helpers left in the project: schema `tmp_build` (raw OSM/OSRM responses) and the `http` and `postgis`
extensions. Safe to remove from the dashboard if you don't plan to refresh outlines or drive times.
